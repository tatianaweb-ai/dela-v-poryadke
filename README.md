# Дела в порядке

Трекер задач и проектов с входом по ссылке из письма и хранением данных в Postgres.
Каждый пользователь видит только свои проекты и задачи — это обеспечено правилами
доступа в самой базе, а не фильтрами в коде.

## Стек

- Next.js 16 (App Router, Turbopack), React 19, TypeScript
- Tailwind CSS 4, lucide-react
- Supabase: аутентификация по magic link + Postgres + Row Level Security
- `@supabase/ssr` — сессия в cookie, продлевается в `src/proxy.ts`

Паролей нет: вход по одноразовой ссылке из письма. Сессию хранит Supabase,
приложение не создаёт и не проверяет её самостоятельно.

## Запуск

Нужен Node.js 20+ и проект Supabase.

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Создайте `.env` рядом с `package.json`:

   ```bash
   cp .env.example .env
   ```

   Значения берутся в панели Supabase: **Project Settings → Data API →
   Project URL** и **Publishable key**.

   Это публичные значения, они попадают в браузер и не являются секретом.
   Service role key приложению не нужен: закрывать чужие данные должны правила
   доступа, а не секретный ключ в коде.

3. Запустите:

   ```bash
   npm run dev      # http://localhost:3000
   ```

## База данных

Схема лежит в `supabase/migrations/` и применяется вручную: откройте
**SQL Editor → New query**, вставьте файлы по порядку и нажмите **Run**.

| Файл | Что делает |
|---|---|
| `0001_projects_tasks.sql` | таблицы `projects` и `tasks`, индексы, включение RLS, правила доступа |
| `0002_user_id_default.sql` | `default auth.uid()` — база сама проставляет владельца строки |

`0001` можно выполнять повторно: политики создаются через `drop policy if exists`.

### Как устроен доступ

У каждой строки есть `user_id` со значением по умолчанию `auth.uid()` — база
подставляет идентификатор вошедшего сама. Клиент это поле не передаёт, поэтому
подставить чужой `user_id` невозможно.

Правила вида `using (auth.uid() = user_id)` применяются на уровне сервера.
Запрос с подменённым чужим идентификатором вернёт ноль строк, а не данные.

Схема проверялась изнутри базы: подмена `request.jwt.claims` на идентификатор
несуществующего пользователя даёт 0 строк в обеих таблицах, и вторым аккаунтом
в браузере чужие задачи не видны.

## Возможности

**Вход.** Ссылка из письма, пароль не запрашивается. Имя спрашивается один раз
после первого входа и хранится в `user_metadata` — его может изменить только
владелец сессии.

**Дашборд.** Приветствие по имени, карточки статистики, ближайшие дедлайны с
подсветкой просроченных и срочных задач, прогресс по активным проектам.

**Проекты.** Создание, редактирование, удаление вместе с задачами проекта
(каскад на уровне базы), прогресс и ближайший дедлайн.

**Задачи.** Создание, редактирование, удаление, отметка выполнения. Поиск по
названию задачи и проекта, фильтры (все / активные / просроченные / выполненные),
фильтр по проекту, сортировка по дедлайну, дате создания и названию.

**Статусы.** Просрочено / Сегодня / Скоро / Запланировано / Выполнено —
цветовой индикатор, текстовая плашка и относительная подпись («Завтра»,
«Через 3 дня», «2 дня назад»). Правило «подпись только если она не повторяет
плашку» собрано в одном компоненте `StatusBadge`.

**Демо-данные.** При первом входе в пустую базу создаются 2 проекта и 5 задач,
чтобы интерфейс не был пустым. Кнопки «Сбросить демо» и «Очистить всё»
работают по-настоящему, то есть чистят базу.

## Структура

```
src/
  proxy.ts                 # продление сессии Supabase (бывший middleware)
  app/                     # layout, страница, стили, иконка
  components/
    Providers.tsx          # провайдеры, заглушка загрузки, вывод ошибки
    AppShell.tsx           # вкладки, модальные окна, выход
    AuthScreen.tsx         # запрос ссылки для входа
    NameSetupScreen.tsx    # имя один раз после первого входа
    Header.tsx             # логотип, навигация, профиль
    Dashboard.tsx          # статистика, дедлайны, прогресс
    StatCards.tsx          # карточки статистики
    ProjectList.tsx        # список проектов
    TaskList.tsx           # список задач, поиск, фильтры, сортировка
    TaskItem.tsx           # одна задача
    TaskModal.tsx          # форма задачи
    ProjectModal.tsx       # форма проекта
    ui/                    # Button, Input, Modal, Toast, ConfirmDialog, ...
  context/
    AppStore.tsx           # состояние приложения, загрузка, CRUD
  lib/
    db/client.ts           # запросы к таблицам projects и tasks
    supabase/config.ts     # чтение переменных окружения
    supabase/client.ts     # клиент для браузера
    supabase/server.ts     # клиент для сервера
    supabase/auth.ts       # имя из user_metadata, проверка почты
    date.ts                # даты, статусы, склонения
    seed.ts                # демо-данные
    validators.ts          # проверка форм
    cn.ts
  types/index.ts
supabase/migrations/       # SQL для ручного применения
```

### Обновление интерфейса

Запись сначала меняет состояние, и только потом уходит в базу: форма отвечает
мгновенно. Если запрос не прошёл, появляется сообщение об ошибке. Чужие данные
при смене пользователя не показываются — пока нет сессии, наружу не отдаётся
ничего.

## Ограничения

- **Письма.** Используется встроенный почтовый сервис Supabase: он предназначен
  для проверки и ограничен по частоте. Для полноценной публикации понадобится
  свой SMTP.
- **Нет ролей и совместного доступа.** Каждый пользователь работает со своим
  набором проектов и задач.
- **Нет офлайн-режима и повторяющихся задач.** Задачи и дедлайны создаются вручную.
- **Нет уведомлений.** Просроченные задачи видно только при открытии приложения.
